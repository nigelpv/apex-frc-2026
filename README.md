# APEX: 2026 REBUILT robot

APEX is a full robot design for the 2026 FRC game REBUILT: CAD with wiring in Onshape, robot code
(Java, WPILib 2026, AdvantageKit, Phoenix 6, PathPlannerLib), and the analysis that picked the
design and tuned the shot tables.

## The design in one paragraph

A 28 x 27 in swerve robot (SDS MK5n R1, Kraken X60 drive) that is 21.75 in tall, so it always
takes the TRENCH and never needs the BUMP. A pivoting over-bumper intake (23 in throat) drops
FUEL into a hopper over a 16 in rotor serializer ("dye rotor") with five pockets. The rotor lines
FUEL up at the rear pocket, which sits on the turret axis; twin belts lift each ball up through
the turret bearing into a 4 in hooded flywheel (2x X60) on a 380 deg turret (Kaydon ring bearing,
X44 70:1, vernier CANcoders for absolute angle). The hood covers 45 to 70 deg launch angles.
Feed rate is 20 FUEL/s, and the robot shoots while driving anywhere in its ALLIANCE ZONE.

## Why this design

- **Shoot from anywhere, while moving.** The turret plus a shoot-on-the-move solver means no
  alignment stop: the robot fires the moment its BUMPERS cross into the ALLIANCE ZONE (G407) and
  keeps firing while it drives. Tables were built with a drag + Magnus model and Monte-Carlo
  make probability (0.9 to 0.99 inside 4.5 m, 0.8+ to 7 m).
- **TRENCH-only height.** 21.75 in vs the 22.25 in TRENCH: the fastest path between the NEUTRAL
  ZONE and the ALLIANCE ZONE, no bump crossing time or tipping risk. The code drops the hood and
  pauses feeding automatically near a TRENCH.
- **The HUB schedule is automatic.** The robot reads the FMS game data (which alliance won AUTO),
  knows when our HUB is active in each SHIFT, spins up early, and only fires shots that will
  count (including the 3 s grace after deactivation). The driver gets a rumble 3 s before our HUB
  turns on.
- **Simple driver job.** Drive and hold intake. Everything else (aim, spin-up, hood, feed,
  legality, TRENCH guard) is the superstructure's job, with operator overrides.

## Onshape

Document "APEX 2026 REBUILT Robot". The Part Studio
**APEX Robot** is the complete robot; it is generated by the Feature Studio **APEX Robot Source**
whose source is `cad/featurescript/v2/` (concatenated in file order). Its configuration panel
switches the intake between deployed and stowed, rotates the turret, lifts the hood and swaps the
bumpers to red. Every part has a BOM name with a
part number (DT-, BU-, RS-, HP-, TU-, IN-, EL-, WR-). COTS parts (MK5n, Krakens, CANcoders,
roboRIO 2, PDH, radio, Limelights, CANivore, battery, breaker) are imported vendor models.
Electrical wiring is modelled as routed cables and bundles with gauge-accurate diameters.

The CAD passes a full interference check: every feature against every other feature has zero
clashes. Cable-to-cable contact only happens where branches join a trunk.

## Robot code

Controls: driver Xbox on port 0, operator Xbox on port 1 (bindings are in the
`RobotContainer` javadoc).

```
cd robot
chmod +x gradlew         # macOS / Linux, once after cloning
./gradlew build          # compile + unit tests
./gradlew simulateJava   # sim with the FUEL simulator; open AdvantageScope on localhost
./gradlew deploy
```

Before the first match on real hardware:

1. Set the swerve encoder offsets with Phoenix Tuner X (`TunerConstants`, all 0 now).
2. Run the "Drive Wheel Radius" and "Drive Simple FF" characterizations from the AUTO chooser.
3. Zero-check the turret: with the turret centred, the vernier solution (`Turret/VernierRad`)
   should read 0 +/- 1 deg; adjust the CANcoder magnet offsets if not.
4. Measure exit speed: shoot from 2, 4 and 6 m and adjust `EXIT_EFFICIENCY` until the shots
   drop through the middle of the opening; then fine-tune in matches with the operator D-pad
   trim (+/-1 % steps).
5. Enter the camera poses for the two fixed Limelights in their web UI (values in
   `VisionConstants`).

### Verification done so far

- The full robot code compiles against the real WPILib 2026.2.1, AdvantageKit 26.0.2 and
  PathPlannerLib 2026.1.2 sources (the AutoLog annotation processor ran), with an API stub for
  Phoenix 6 that was cross-checked against CTRE's examples and the AdvantageKit TalonFX template.
  That check found and fixed one real bug (`Shooter.idle()` clashed with `Subsystem.idle()`).
- 17 unit tests pass: HUB schedule, vernier solve and fault rejection, every shot-table row and
  every interpolated shot against the flight model, and shoot-on-the-move landing inside the
  HUB opening at up to 3 m/s and 2 rad/s.
- Not yet done: a `gradlew build` and a full sim run on a machine with the WPILib toolchain
  (this environment has no access to the FRC Maven servers).
